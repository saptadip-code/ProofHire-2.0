## Explainability contract (A-G4) — implemented
Files (M1): `backend/app/ml/evidence.py`, `checklist.py`, `entities.py`, `template_explainer.py` (rewritten in A-G5, see below), result cache in `pipeline.py`; tests `ml/tests/test_evidence.py`, `test_checklist.py`, `test_entities.py`, `test_pipeline_explainable.py`.
**Evidence (A7)** `evidence.build_evidence(listing, features, model) -> list[EvidenceItem]` (`features` = `features.build_row(listing)`, `model` = the fitted sklearn Pipeline, `None` -> observed only). Observed codes (17, A7 table order, severity, direction): `UPFRONT_FEE` 3 up, `PERSONAL_DATA_REQUEST` 3 up, `GUARANTEED_OFFER_CLAIM` 2 up, `UNREALISTIC_PAY` 3 up (`salary_ratio_vs_role >= 3`), `FREE_EMAIL_CONTACT` 2 up, `EMAIL_DOMAIN_MISMATCH` 2 up, `NO_COMPANY_WEBSITE` 1 up, `MESSAGING_APP_ONLY` 2 up, `URGENCY_PRESSURE` 1 up (`urgency_hits >= 2`), `NO_INTERVIEW` 2 up, `VAGUE_DESCRIPTION` 1 up (`desc_words < 40`), `VAGUE_REQUIREMENTS` 1 up (`req_words < 8`), `EXCESSIVE_HYPE` 1 up (`exclaim_count >= 4` or `caps_ratio > 0.25`), `CORP_EMAIL_MATCHES_WEBSITE` 1 down, `DETAILED_REQUIREMENTS` 1 down (`req_words >= 25`), `STRUCTURED_INTERVIEW` 1 down, `PAY_IN_EXPECTED_RANGE` 1 down (`0.5 <= ratio <= 1.8`). Model codes: `MODEL_TERM` (TF-IDF n-gram) / `MODEL_FEATURE` (structured), severity 2. Rules decide from the SAME `features` dict training used, so rule and model never disagree about a derived value. Constants: `OBSERVED_CODES` (17), `MODEL_CODES` (2), `ALL_EVIDENCE_CODES` (19 strings = the valid checklist trigger codes), `EVIDENCE_CATALOG`, `MAX_EVIDENCE_ITEMS = 12`.
Observed items: `weight` null; `snippet` = exact contiguous span of the submitted title / description / requirements (regex match span, original case and whitespace, <= 120 chars) for `UPFRONT_FEE` (extended over a directly following amount, e.g. `registration fee of Rs 1,499`), `PERSONAL_DATA_REQUEST`, `GUARANTEED_OFFER_CLAIM`, `URGENCY_PRESSURE` (first phrase), `EXCESSIVE_HYPE` (first exclamation clause, else first run of capitals); the exact submitted `contact_email` (original case) for `FREE_EMAIL_CONTACT`, `EMAIL_DOMAIN_MISMATCH`, `CORP_EMAIL_MATCHES_WEBSITE`; `null` for every rule that rests on an absent / numeric / enum value (and when the only trigger is the `upfront_fee_amount` field). Snippets are never composed or paraphrased.
Model items: contribution = `coef_i * x_i` where `x_i` is the output of the fitted `ColumnTransformer` (TF-IDF weight, standardised number, 0/1 flag, one-hot); intercept excluded; `weight` = contribution rounded to 4 dp; top 5 positive (`increases_risk`) + top 2 negative (`decreases_risk`) where available; zero contributions skipped. Labels: `Wording often seen in risky|legitimate listings: '<term>'` (MODEL_TERM) / `Model signal: <human phrase>` (MODEL_FEATURE). `snippet` null. Tested: `sigmoid(sum(contributions) + intercept) == risk_score` (4 dp).
Order / ids: observed by severity desc (stable, A7 table order on ties), then model by weight desc (positive first); truncated to 12 FROM THE TAIL; ids `E1..En` assigned after ordering. If model evidence cannot be computed (pipeline not ColumnTransformer + linear classifier) it is skipped with an ERROR log and observed evidence is still returned.
**Checklist (A8)** `checklist.build_checklist(evidence, library_path=None) -> list[ChecklistItem]` reads `backend/app/data/checklist_library.json` (M4-owned, read-only for M1; cached by modification time). Match = item trigger in the evidence codes (observed or model); `"*"` always-on, max 4 (priority, then library order); dedupe by `code` (first wins); sort priority then (evidence-triggered before always-on) then library order; max 10; returned without ids, `done: false`. Missing / unreadable library: empty checklist + ONE ERROR log per file state + `checklist.library_status()` -> `{status: ok|partial|invalid|missing, path, items, problems}`; no substitute content is ever invented. Invalid items (bad priority, text > 500 chars, empty triggers, missing code) are skipped and reported; unknown trigger codes are kept but reported (`partial`).
**Entities (A9)** `entities.extract_entities(listing)`; order `email, email_domain, phone, website_domain, company_name`; only non-empty valid values. Email lower-cased/trimmed (must match the schema email regex); `email_domain` and `website_domain` are NEVER emitted for `FREE_MAIL_DOMAINS` (the free-mail `email` itself is still returned); phone: spaces/hyphens/parentheses ignored, leading `+91` removed, one leading `0` removed, must be exactly 10 digits else skipped; website host without scheme, credentials, port, path and `www.`; company: lower-case, apostrophes removed, other punctuation -> space, trailing `inc ltd pvt llp private limited technologies solutions` stripped (kept as-is if stripping would leave nothing). Helper normalisers are public (`normalize_email`, `email_domain_of`, `website_domain`, `normalize_phone`, `normalize_company_name`). Module imports stdlib only at import time (the pydantic `Entity` is imported inside `extract_entities`) so `features.py` keeps its stdlib-only inference path.
**Explanation (interim, deterministic)** `template_explainer.build_template_explanation(risk_level, evidence) -> Explanation(source="template")`. Receives only the already-decided level and a COPY of the evidence list, so it cannot change score, level or evidence. Concerns: one per observed risk-increasing item (max 5, cites that item's id) plus, at medium/high risk, one pattern-level concern citing up to 3 model risk-increasing ids. `what_to_verify` max 4. Never states that an employer is fraudulent.
**Result cache (A12)** in `pipeline.py`: key = SHA-256 of canonical JSON `{listing: ListingInput.model_dump(mode="json"), model_version, model_sha256, thresholds, llm: <effective mode>}`; 100 entries (LRU), TTL 600 s, deep copies in/out, cleared by `reload_model()`. `llm` = `with_llm AND LLM_ENABLED`, so an evidence-only call can never be handed an LLM-enabled entry (and vice versa) now that A-G5 has landed. A template produced because the LLM was wanted but failed is NOT stored (the next identical request retries); LLM explanations and deliberate templates are. A cached LLM result is returned with `llm_meta.latency_ms = 0`. Only listing fields reach the key (no user id / JWT / owner token ever enters this module). Failed assessments are not cached. `predict_listing()` bypasses the cache (score only).

## LLM contract (A-G5) — implemented
Files (M1): `backend/app/ml/llm_client.py`, `backend/app/ml/template_explainer.py`; tests `ml/tests/test_llm_client.py`, `test_template_explainer.py`, `test_llm_pipeline.py`; `ml/tests/conftest.py` now strips every `LLM_*` variable before each test.
Public: `llm_client.generate_explanation(risk_level, evidence, checklist_hints) -> (Explanation, LlmMeta)` (never raises), `llm_enabled()`, `circuit_open()`, `clear_cache()`, `load_config()`, `validate_explanation()`, `SYSTEM_PROMPT_A10` (A10 text verbatim) + `SYSTEM_PROMPT` (adds one untrusted-input security sentence). `template_explainer.build_template_explanation(risk_level, evidence, checklist_hints=None)` (3rd argument is new and optional).
Flow: disabled -> template | no key -> template (`no_api_key`) | cache hit | breaker open -> template (`circuit_open`) | limiter refuses -> template (`local_rate_limit`) | primary call | on timeout / HTTP 429 / HTTP 5xx / unparsable JSON or wrong keys (`bad_json`, `bad_schema`) ONE call to the fallback if configured | else template. Worst case 2 HTTP calls, each capped by `LLM_TIMEOUT_SECONDS`.
`llm_meta` (fields unchanged: `provider, model, latency_ms, success, error_code`): LLM answer -> provider `groq`/`openrouter`, success true, error_code null; deliberate template (LLM disabled or `with_llm=false`) -> `template`/`template`, success **true**, null; template after the LLM was wanted -> `template`, success **false**, error_code one of `no_api_key, circuit_open, local_rate_limit, timeout, network_error, client_error, http_<status>, bad_json, bad_schema, unsafe_content, no_valid_concerns, internal_error`, or `<primary>><fallback>` when both failed; a cache hit repeats provider/model with `latency_ms` 0. Backend suggestion for `llm_calls` / the dashboard: count `provider='template' AND success=false` as template fallbacks; do not insert a row for `provider='template' AND success=true` unless a call row is wanted for every assessment (Member 3's choice).
Validation of the model's answer: JSON object with `summary` (str), `key_concerns` (list), `what_to_verify` (list); a concern is dropped unless its text is a string and `evidence_ids` is a non-empty list of strings that ALL exist among the (max 8) evidence ids sent; non-string list items dropped; at most 5 + 5 items; summary shortened to 700 chars; wording rejected (summary: whole answer; concern / verify item: that item) when it calls the employer a scam / fraud / fake, is definite (`definitely`), makes legal claims, vouches (`is safe / legitimate / verified`), mentions the score or a probability, contradicts the actual risk level, or contains a link; no valid concern left -> template.
Cache: key = SHA-256 of risk level + sorted evidence (id, label, snippet, type, direction) + checklist hints; 256 entries LRU, TTL 24 h; re-validated against the current ids on every hit; failures never cached. Rate limiter: sliding 60 s window, `LLM_RPM_LIMIT` requests; breaker: 3 consecutive failures -> open 120 s -> one recovery attempt.
Dependency: `httpx` (already in the guidebook requirements for both files; imported lazily, only when a request is made).
