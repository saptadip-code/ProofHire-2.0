## 1. How Member 3 calls the ML code (in-process, no HTTP)
```python
from app.ml.pipeline import assess_listing, load_model, model_status, ModelNotLoadedError
from app.schemas.ml_schemas import ListingInput          # request model, Section 5.2
from app.ml.entities import FREE_MAIL_DOMAINS            # shared free-mail list (B5)
```
* **Startup (lifespan):** call `load_model()` once. It never raises: if the artifact is missing, corrupt, built with another
  scikit-learn than the one running, or has a different feature order, it logs the reason and `model_status()["loaded"]`
  is `False`. There is no stub or fallback model.
* **`POST /assessments`:** `ml = await run_in_threadpool(assess_listing, listing)` (it can wait up to 12 s on the LLM).
  Catch `ModelNotLoadedError` and answer 503 `model_unavailable` (Section 5.5). Nothing else is raised for explanation or
  LLM problems: an LLM failure still returns a result with `explanation.source == "template"`.
* **Result (`MlResult`):** `risk_score`, `risk_level`, `thresholds`, `model_version`, `evidence[]` (ids `E1..En`),
  `explanation`, `checklist[]` (**no ids**: the backend assigns them), `entities[]`, `llm_meta`. Store `llm_meta` in
  `llm_calls` (provider `groq` / `openrouter` / `template`, `success`, `error_code`, `latency_ms`).
  The backend adds the DB-only fields (`assessment_id`, `created_at`, `connections`, `report_count_approved`,
  `owner_token`, `disclaimer`).
* **`GET /health`:** use `model_status()` -> `{loaded, model_version, trained_at, sklearn_version, llm_enabled}`.
* `assess_listing()` is a pure function (no DB, no auth); identical listings are served from a 100-entry / 10-minute
  in-memory result cache (a failed LLM attempt is never cached).
* `checklist` stays `[]` until `backend/app/data/checklist_library.json` (Member 4) exists and is valid; assessments still work.

## 2. ML HTTP endpoints (`/api/v1/ml`) and authentication
| Endpoint | Auth | Returns |
|---|---|---|
| `GET /health` | none | `{loaded, model_version, trained_at, sklearn_version, llm_enabled, llm_circuit_open}` |
| `GET /model-info` | none | `model_meta.json`; `Cache-Control: public, max-age=300`; `ETag` = model sha256; 304 on match; 503 if not loaded |
| `GET /metrics` | none | `metrics.json`; same caching; 503 if not loaded |
| `POST /predict` | key | `{risk_score, risk_level, thresholds, model_version}`; no evidence, no LLM, no DB |
| `POST /evidence` | key | `{risk_score, risk_level, evidence[]}`; never calls the LLM |
| `POST /explain` | key | full `MlResult` (no DB fields); LLM or template |
| `POST /extract-entities` | key | `{entities[]}`; needs no model |
| `POST /reload` | key | `{reloaded: true, model_version, sha256}`; 500 and the OLD model stays if the new artifact is invalid |

**Authentication:** the five POST endpoints require header `X-Internal-Key` equal to env `INTERNAL_API_KEY`. If that variable
is empty (local dev) the check is skipped. Missing/wrong key -> 401 `unauthorized`. GET endpoints are public. The backend
does not call these over HTTP; they exist for Swagger demos, smoke tests and the retrain workflow. On Render
`INTERNAL_API_KEY` is generated by `render.yaml`, so POSTs need the key there.

## 3. Environment variables (no secrets in git; `backend/.env.llm.example` has the full list)
| Variable | Used for |
|---|---|
| `INTERNAL_API_KEY` | `X-Internal-Key` for ML POST endpoints (empty = no check) |
| `LLM_ENABLED` | `true` turns the LLM on; anything else = template only (default off) |
| `LLM_API_KEY`, `LLM_BASE_URL`, `LLM_MODEL` | primary provider (Groq, OpenAI-compatible) |
| `LLM_FALLBACK_API_KEY`, `LLM_FALLBACK_BASE_URL`, `LLM_FALLBACK_MODEL` | optional OpenRouter fallback (needs key AND model) |
| `LLM_TIMEOUT_SECONDS` 12, `LLM_MAX_TOKENS` 450, `LLM_TEMPERATURE` 0.2, `LLM_RPM_LIMIT` 20, `LLM_CACHE_SIZE` 256, `LLM_CACHE_TTL_SECONDS` 86400 | tuning |
| `PROOFHIRE_TEST_ARTIFACT_DIR`, `PROOFHIRE_TEST_REPORTS_DIR` | **tests only** (set by `ml/retrain.py` to test a candidate); the service never reads them |

The product works with every `LLM_*` variable removed (deterministic template explanations).

## 4. Artifacts and reload
* Files: `backend/app/ml/artifacts/{model.joblib, model_meta.json, metrics.json}` (committed to git; Render's disk is ephemeral).
* Load checks (`app/ml/model_store.py`): meta keys and version format, `sklearn_version` equals the RUNNING scikit-learn
  (pinned 1.7.2), `feature_order` equals `features.FEATURE_ORDER`, `sha256_model` (verified BEFORE unpickling),
  `joblib.load`, one warm-up prediction.
* `POST /ml/reload` / `pipeline.reload_model()`: validates first, swaps the model atomically under a lock, clears the result
  cache, the LLM cache and the checklist cache. The circuit breaker and rate limiter are deliberately NOT reset. On any
  failure the previous model keeps serving. On Render a reload only helps if the files changed without a redeploy
  (normally they change by git push + redeploy).

## 5. Retraining (laptop or CI only, never on Render)
```
python scripts/export_feedback.py                       # Member 3/4: MySQL -> ml/data/feedback.csv
PYTHONPATH=backend python ml/retrain.py --feedback ml/data/feedback.csv --feedback-weight 3
PYTHONPATH=backend python ml/retrain.py --dry-run ...   # evaluate + print the gates, never promote
```
**Feedback CSV:** same listing columns as the synthetic CSV, with at least `title, company_name, description, label`;
optional `is_synthetic_demo`, `listing_id`, `report_count_approved`. Only rows with `label = 1` (approved report), not demo
rows, not `SYN-` ids, `report_count_approved >= 1` when present, complete and de-duplicated are used. Rows labelled 0
are dropped: a listing with no report is never treated as legitimate. Zero eligible rows -> nothing happens.
Feedback is positive-only, so it can bias the model toward "risky"; this is stated in `metrics.json` limitations.

**Promotion gates (all must pass; computed live for the production model and the candidate on the same data):**
synthetic-test PR-AUC drops by <= 0.01; hand-written recall does not drop; pattern-holdout recall does not drop;
`model.joblib` < 10 MB; `pytest ml/tests -q` passes against the candidate. **Fail closed:** if a comparison cannot be
computed (for example `demo_data/handwritten_eval.csv` is missing, the production model cannot load, pytest is not
installed) the gate fails and the production artifacts are not touched. There is no override flag.
On success: artifacts and `ml/reports/` are replaced atomically, the version bumps (PATCH, or MINOR if the feature set
changed) and a dated line is appended to `ml/CHANGELOG.md`. Then commit, open a PR and let Render redeploy.
**Until Member 4 delivers `demo_data/handwritten_eval.csv` (60 rows), `retrain.py` cannot promote anything.**

Rebuild without feedback (for example after a scikit-learn change): `PYTHONPATH=backend python ml/rebuild_artifacts.py`
(refuses to run unless scikit-learn is the pinned 1.7.2).
